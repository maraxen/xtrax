# Brainstorm: E1 signature-inference core: how should xtrax derive AxisSpec batch-planning roles and the Bundle pytree schema from a typed pure JAX function (jaxtyping annotations + jax.eval_shape), with a Tyro-backed CLI downstream?

## Problem Frame
FIXED constraints (cannot change): (1) eval_shape is the structural oracle — Bundle structure + field names come from it, not from annotations. (2) jaxtyping stays optional — inference must work (perhaps with less role precision) when no jaxtyping annotations are present; it can never be a hard runtime dependency. (3) Output must satisfy existing seams unchanged: produce a valid list[AxisSpec] for RunSpec.axes (tiling/plan.py:26) and a Bundle conforming to FeatureBatch/InputResolver (run/resolver.py:21,41) and StageBundle's Optional[Callable] field rule. (4) eval_shape purity requirement (no side-effecting tree_unflatten) and symbolic-dim equality being unsound are facts to design around, not negotiate. (5) CLI parsing delegates to Tyro — not in scope to reconsider.

NEGOTIABLE (the forks): how dim-names map to roles; where cardinality comes from; the exact @axis_config decorator shape; whether field-name recovery uses register_pytree_with_keys vs dataclass/eqx.Module introspection; whether CarrySpec auto-derivation is in E1 or deferred; whether Bundle is emitted as a runtime schema object or libcst-codegened class. Also negotiable: how much "magic" vs explicitness we accept — that's the core architectural tension the competing factions should stake out. Frame confirmed on my end; please confirm and move us to divergence.

## Idea Pool
- [ai] FACTION A — THIN ORACLE / EXPLICIT: eval_shape recovers structure+field-names (via jax.tree_util.tree_flatten_with_path → GetAttrKey). ALL roles, cardinality, and knobs come from an explicit @axis_config(AxisConfig(...)) decorator that 1:1 mirrors AxisSpec fields; jaxtyping is NOT parsed for roles (treated as optional runtime validation only). Bundle = runtime schema object (BundleSchema dict of path→ShapeDtypeStruct); NO libcst codegen. CarrySpec deferred unconditionally. Cardinality declared explicitly, never inferred. STRENGTH: exactly one source of truth per concern; failures point at the decorator; robust against jaxtyping version drift & multi-word/arithmetic dim strings. WEAKNESS: a decorator on every function is a SECOND source of truth that can drift from the annotation — abandons the "signature is source of truth" ergonomic win (20 stage fns = 20 decorators to maintain).
- [ai] FACTION B — ANNOTATION-NATIVE / MAXIMAL INFERENCE: the signature IS the spec. Parse jaxtyping dim-name strings as the PRIMARY role source via a versioned ROLE_TABLE (batch→non-dedup, atoms/res→dedup+heterogeneous, seq→sequence…); recover dim strings via typing.get_type_hints(fn, include_extras=True) + reading Annotated.__metadata__[*].dim_str. @axis_config exists ONLY as field-by-field override sidecar. Cardinality: concrete from eval_shape shape, else jax.export symbolic dim (sentinel + symbolic_name). Field names via dataclasses.fields / eqx Module fields / register_pytree_with_keys GetAttrKey.attribute (public since JAX 0.4.14). CarrySpec AUTO-derived from RollingFn (eval_shape on (carry,x)→(carry,y); axis_name matched by cardinality). Bundle = libcst-codegened StageBundle subclass + .pyi stub. STRENGTH: annotation already written → zero boilerplate, kills staleness/divergence bugs across the whole library. WEAKNESS: dim-name is a CONVENTION not a contract — `Float[Array,"b n d"]` silently yields zero role inference, no error; jaxtyping __metadata__/dim_str is private and has shifted across minor versions (must pin+test per release); optional-dep ImportError handling doubles branching.
- [ai] FACTION C — PROGRESSIVE REFINEMENT / HYBRID: eval_shape is the bedrock oracle — runs unconditionally and ALWAYS yields a structurally valid BundleSchema + plan with conservative defaults (Tier 3: leading axis = batch, cardinality from shape). jaxtyping dim-names are an OPTIONAL Tier-2 precision upgrade; @axis_config is Tier-1 override that always wins. Single precedence fn resolve_axis_role(explicit_cfg > dim_name role > structural default) — Tier 3 NEVER consults annotation state, so jaxtyping is off the critical path and the core is testable without it. Cardinality: concrete from shape + optional override + symbolic string reserved for codegen only (planner rejects symbolic unless allow_symbolic). Field names via dataclass/eqx walk; Bundle = plain BundleSchema object (MVP). CarrySpec DEFERRED but SEAMED: BundleSchema.carry_specs: list|None passthrough + a no-op CarryInferencePass protocol hook E1.x swaps in. Bundle emission: schema-object MVP; emit_bundle_class via libcst is opt-in behind xtrax[codegen]. STRENGTH: cannot fail silently at the wrong boundary; graceful degradation; ships without jaxtyping on the hot path. WEAKNESS: two annotation tiers risk inconsistency, and "progressive" can become "never finished" — if Tier-3 defaults are good enough, Tier-2/1 see no usage and stay untested. MITIGATION (load-bearing): gate E1-done on test coverage of ALL THREE tiers + the real dim-name vocabulary.
- [user] Three competing approaches developed in full (recorded to the pool): A) Thin Oracle/Explicit — eval_shape for structure, ALL roles via explicit @axis_config, no dim-name parsing, no codegen, CarrySpec deferred. B) Annotation-Native/Maximal — parse jaxtyping dim-names as primary role source via a ROLE_TABLE, @axis_config override-only, CarrySpec auto-derived from RollingFn, libcst-codegen the Bundle class. C) Progressive Refinement/Hybrid — eval_shape mandatory & sufficient with conservative defaults, dim-names as optional Tier-2 refinement, @axis_config Tier-1 override, 3-tier precedence (resolve_axis_role), Bundle schema-object MVP with codegen opt-in, CarrySpec deferred-but-seamed.
- [user] The central architectural tension is MAGIC vs EXPLICITNESS, and it bites hardest on Fork 1 (dim-name→role). A buys robustness by abandoning the "signature is source of truth" win (decorator becomes a second source of truth that drifts). B buys maximal ergonomics by betting on a fragile convention (jaxtyping private internals + silent zero-inference on non-conventional names). C subordinates both: structure is never blocked on annotations, annotations only sharpen. The fixed constraint "jaxtyping stays optional, eval_shape is the structural oracle" already rules OUT B's stance that dim-names are primary/load-bearing — B's CarrySpec auto-derivation and mandatory codegen also widen E1 scope beyond a keystone. I'm ready to converge; before evaluation, dispatch an adversarial critic on the leading candidate.

## Decision Log
- [ACCEPT] E1-MVP six-fork resolution (C-AMENDED, MVP-scoped): (1) dim-name→role = optional Tier-2 behind capability-probed adapter, DEFERRED out of MVP; (2) cardinality = concrete from eval_shape shape + optional @axis_config override; symbolic reserved for codegen; (3) @axis_config = Tier-1 override sidecar on the fn object, field-by-field merge; (4) Bundle structure+field-names = eval_shape output pytree + tree_flatten_with_path/GetAttrKey (empirically confirmed working); (5) CarrySpec = DEFERRED but seamed (BundleSchema.carry_specs passthrough + no-op CarryInferencePass hook); (6) Bundle emission = runtime BundleSchema object for MVP, libcst codegen opt-in follow-on.: eval_shape is the reliable jaxtyping-free structural bedrock (verified: ShapeDtypeStruct + GetAttrKey field recovery work on the installed stack). Tier-3 default changed from "leading axis = batch + dedup" to fail-loud UNKNOWN after the critic empirically demonstrated the batch default silently corrupts a residues-first protein function (dedup collapses distinct residues, no error). Tier-2 (jaxtyping dim-name roles) and codegen and CarrySpec are deferred because (a) jaxtyping internals are private/version-fragile and must sit behind a tested capability-probed adapter, and (b) pre-mortem mitigation #1 gates Tier-2 on a real aminx caller proving demand — absent that, ship A-shaped. Scope split keeps the MVP to one capability / ≤8 ACs (INVEST-S).

## Pre-mortem Record
**User:** Pre-mortem — three ways C-AMENDED is dead in 6 months:

1) OVER-ENGINEERED INTO A (most likely). Tier-2 dim-name inference saw near-zero adoption: real users' dim vocabularies never matched BATCH_ALIASES often enough to trust, so everyone added @axis_config anyway to silence the fail-loud UNKNOWN errors. Result: we shipped three tiers but only Tier-1 (@axis_config) + Tier-3 (fail-loud) are ever exercised — exactly Faction A, but carrying the dead weight of an unused jaxtyping adapter, role table, and UNKNOWN-plumbing. The runner-up steelman predicted this. Trigger to watch: if the spec's own examples all need @axis_config, Tier-2 has no reason to exist.

2) THE BEDROCK BETRAYED US. We declared eval_shape "always correct," but a domain function had a data-dependent/side-effecting custom pytree unflatten (the documented purity gotcha) — eval_shape returned a structure that silently diverged from the real runtime batch, so the derived BundleSchema was confidently wrong in the ONE layer we never guarded. No fail-loud there because we trusted it unconditionally.

3) THE OPTIONAL DEP BROKE LOUDLY. jaxtyping 0.4.x reorganized _array_types; the capability probe did its job and disabled Tier-2 — but for the cohort who DID adopt dim-name roles, a routine `pip install -U` flipped every inferred axis to UNKNOWN overnight, and pipelines that ran yesterday failed loud today. "Optional and probed" still produced a silent-capability-regression that read as a breaking change.

Mitigations to bake into the spec: (1) gate E1-done on a real aminx/protein caller actually using Tier-2 (not a toy) — if it can't, demote Tier-2 to a follow-on and ship A-shaped; (2) add a purity/consistency guard — verify eval_shape structure against one real concrete batch before trusting it, fail loud on mismatch (the bathos "verify the measurement pipeline" discipline); (3) treat the adapter SUPPORTED flag as a pinned, tested contract with an explicit jaxtyping version range, and surface a one-time loud warning (not silent) when Tier-2 capability changes between runs.

**Then** (E1-MVP scope — bedrock + Tier-1 + Tier-3 fail-loud + purity guard; Tier-2/codegen/CarrySpec are OUT, see TBDs):

- [ ] **AC1 — Structural extraction.** Given a typed pure fn and abstract inputs, `infer_bundle(fn, abstract_inputs)` returns a `BundleSchema` whose fields mirror the `jax.eval_shape` output pytree, with field names recovered via `jax.tree_util.tree_flatten_with_path` (`GetAttrKey.attribute` for dataclass/`eqx.Module`/keyed nodes; positional `out_0…` fallback otherwise) and a `ShapeDtypeStruct` per leaf. No real compute runs.
- [ ] **AC2 — Zero-config still succeeds.** Given a fn with NO `@axis_config` and NO recognized annotations, `infer_bundle` still returns a valid `BundleSchema` and a `list[AxisSpec]` covering every input axis; structure never fails for lack of annotations.
- [ ] **AC3 — Fail-loud on ambiguity (keystone).** Given an axis whose role is unresolved (no Tier-1 override, MVP has no Tier-2), its `AxisSpec` carries an `UNKNOWN` role sentinel; passing such a schema to any batching-sensitive operation (e.g. `BatchPlanner.plan` for that axis, or dispatch) raises a clear `AmbiguousAxisError` naming the axis and how to resolve it. It is NEVER silently defaulted to `batch`/`dedup_eligible`.
- [ ] **AC4 — Tier-1 override resolves.** Given `@axis_config(...)` on the fn declaring an axis's name/role/knobs, the derived `AxisSpec` for that axis reflects the override (field-by-field merge over structural defaults), and the axis is no longer `UNKNOWN`.
- [ ] **AC5 — Purity/consistency guard.** Given one concrete representative batch, `infer_bundle(..., verify_against=batch)` compares the `eval_shape`-derived structure to the concrete batch's structure and raises `StructureMismatchError` on divergence (guards the side-effecting/data-dependent `tree_unflatten` gotcha). Default-on when a concrete sample is available.
- [ ] **AC6 — Seam conformance.** The derived `list[AxisSpec]` is accepted unchanged by `RunSpec.axes` (`tiling/plan.py:26`) and `BatchPlanner.plan`; the `BundleSchema` is consumable by an `InputResolver` to produce a `FeatureBatch` (`run/resolver.py:21,41`) and satisfies `StageBundle`'s `Optional[Callable]` field rule (`stages/bundle.py:22`). No seam signatures change.
- [ ] **AC7 — jaxtyping is optional.** With jaxtyping NOT installed, AC1–AC6 all pass (import succeeds, inference runs, axes resolve via `@axis_config` or `UNKNOWN`). No hard import of jaxtyping on any MVP code path.
- [ ] **AC8 — Parity oracle.** For a representative subset of the 16+ existing hand-written `AxisSpec` sites, a `@axis_config`-annotated function reproduces the same `AxisSpec` fields (name, cardinality, default_batch_size, flags) the site declares by hand — proving E1 can replace the hand-declaration.
