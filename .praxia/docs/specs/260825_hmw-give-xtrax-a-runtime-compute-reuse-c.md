# Brainstorm: HMW: give xtrax a runtime compute-reuse capability layer (CSE detection reports, content-keyed memoization of pure jitted inference calls, data-dependent batch-row dedup synthesis) without violating JAX purity, jit caching semantics, or xtrax fail-loud API conventions?

## Problem Frame
FIXED CONSTRAINTS: (1) No jaxpr rewriting - detection/report only; XLA owns intra-program CSE. (2) No silent caching anywhere: every cache/dedup activation is opt-in, observable via explicit report or config flag; fail-loud on ambiguity per xtrax convention (AmbiguousAxisError precedent). (3) JAX purity is a hard admission precondition for memoization: impure functions are rejected with a typed error, not warned about. (4) PRNG discipline: jax.random keys are values; same-key-same-result is correct semantics so keys may be part of content keys. (5) Async dispatch safety: cached outputs must be block_until_ready() before retention. (6) Zero new required params on existing public APIs; additive-only surface changes. NEGOTIABLE: which of components a/b/c ship in v1 vs deferred; whether memo wrapper lives in inference/ as decorator or standalone module; whether dedup synthesis auto-wires into BatchPlanner.plan() Phase 0b or is a separate advisory pre-pass; report emission format details; LRU sizing policy and eviction telemetry.

## Idea Pool
- [ai] ARCHITECTURE AXIS - four competing integration architectures:
- [ai] A1. 'Decorator-first': memo wrapper as @memoize_jaxpr decorator exported from xtrax.inference, user applies manually; CSE reporter as standalone analyze_cse(fn, abstract_inputs) function; dedup synthesis stays manual via existing DedupSpec. Minimal coupling.
- [ai] A2. 'Planner-integrated': all three components wired through BatchPlanner - plan() accepts optional reuse_policy parameter; CSE report becomes a plan() side-output; dedup synthesis auto-fires in Phase 0b when host-sampled row hashes show duplication above threshold. Deep integration, one entry point.
- [ai] A3. 'CLI/report-first': ship xtrax explain --cse first (detection + advisory output), memo wrapper second-class internal utility, defer dedup synthesis. Evidence-before-machinery philosophy.
- [ai] A4. 'Graph-level collapse': extend HostPrepGraph to hash-collapse identical nodes at composition time and route repeated subgraphs through one memo node; jaxpr-level analysis demoted to debug tooling.
- [ai] CORRECTNESS/SAFETY AXIS - three competing admission-control designs for the memo wrapper:
- [ai] B1. 'Static purity check only': admit functions based on jaxpr inspection at wrap time (no stateful primitives: random without explicit keys, i/o, host callbacks); reject others with typed MemoImpurityError.
- [ai] B2. 'Runtime verification': first call runs twice (or on sampled inputs) comparing outputs to detect impurity dynamically before enabling cache hits; higher confidence, 2x cold-start cost.
- [ai] B3. 'Caller-attested': purity is caller-declared like existing DedupSpec/DedupFn convention (caller declares, library trusts but documents); zero overhead, matches xtrax 'caller declares' pattern, weakest guarantee.
- [ai] COST-GATING AXIS - when does reuse actually pay? Competing gating policies:
- [ai] C1. 'Static estimate gate': use lowered_memory_estimate + eqn FLOP heuristic at wrap time; refuse to memoize if estimated op cost < hash cost (hash cost modeled as bytes-touched * host bandwidth).
- [ai] C2. 'Adaptive runtime gate': track observed hit rate + op wall time per cache entry; disable caching dynamically below profitability threshold, emit telemetry.
- [ai] C3. 'No gate, caller decides': expose raw wrapper + hit-rate counter; profitability is the caller's problem. Simplest, most footgun-prone.
- [ai] DEDUP-SYNTHESIS AXIS - how should component (c) detect duplicated batch rows:
- [ai] D1. 'Host-side full hash': hash all N rows on host (np.ascontiguousarray + xxhash), exact detection, O(N) host transfer - defeats the purpose for large N.
- [ai] D2. 'Sampled host hash': hash a bounded sample (e.g. min(N, 4096) rows), estimate duplication ratio, only synthesize DedupSpec if ratio exceeds threshold; probabilistic, cheap, k-bucketing absorbs error.
- [ai] D3. 'In-device canonicalization': jnp.unique inside a small jitted kernel to compute unique_indices/index_map on device; exact but adds compiled kernel and device-host sync for K.
- [ai] D4. 'Defer entirely': keep caller-declared DedupSpec as the only path; ship a doc recipe showing users how to build specs from np.unique themselves. Zero new code.

## Pre-mortem Record
**User:** Pre-mortem: 6 months in, the feature failed because of silent cache staleness in long-running controller loops. Root cause chain: a scoring function closed over a config dict that the loop mutated between iterations; the caller attested pure=True once at wrap time; the static screen saw a clean jaxpr (the mutation is host-side, invisible); the cache served iteration-2 results computed from iteration-1's config values; fitness scores drifted subtly, ratchet decisions degraded, and nobody noticed for weeks because hit-rate telemetry looked healthy. The failure was not a crash - it was plausible-but-wrong results with healthy-looking observability. Mitigation to bake into the spec: (1) cache keys must incorporate a user-supplied salt/version field that loop code bumps on any state change outside the argument pytree, documented as REQUIRED for closure-carrying wrappers; (2) telemetry must include an 'attestation age' counter and a cheap periodic spot-check mode (recompute every Kth call and compare, off by default) so wrong-cache-hit can be detected, not just suspected.
