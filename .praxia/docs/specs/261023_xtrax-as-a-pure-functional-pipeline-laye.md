# Brainstorm: xtrax as a pure-functional pipeline layer: users write typed pure functions; xtrax auto-bundles inputs/outputs from types and resolves each piece's runtime implementation (vmap / ChunkedMap / Scan / while_loop / Pallas kernel vs reference) from a runtime context (differentiable?, export target, backend, kernels, memory budget), using AST/CST/jaxpr analysis to infer and verify what the user did not declare.

## Problem Frame
Frame.
FIXED: (1) user code is plain JAX — pure functions over pytrees; no framework base class required (user decision: plain-JAX layer). (2) Any implementation choice must be semantically invisible: every resolution of a declaration computes the same function (up to float reassociation tolerance) as a reference resolution; resolution changes cost, never meaning. (3) Unsatisfiable contexts fail loud at resolve time, before tracing, naming the constraint (e.g. export + WhileCarry), never silently degrade. (4) Existing strategies, BatchPlanner, executor, export composer and jaxpr toolkit are reused; consumers (aminx, plegadx, …) keep working through a migration window. (5) Kernels are pluggable implementations; xtrax ships the seam, not the kernels (user decision). (6) No hidden global state: the context is an explicit value.
NEGOTIABLE: how much is declared vs inferred (annotations vs jaxpr inference vs AST); granularity of context (per pipeline vs per stage); whether resolution happens eagerly (a plan object) or lazily at first call; how users override a choice; whether AST/CST is used at all (jaxpr may suffice); the surface API shape (decorators, combinators, a graph builder).
NON-GOALS (orchestrator's call): a new tracing system or IR replacing jaxpr; a scheduler for multi-host/distributed placement; automatic kernel generation.
ANTI-GOALS: magic that changes results; a DSL users must learn instead of JAX; inference that is unverifiable (an inferred property must be checked on the jaxpr or declared).

## Decision Log
- [REJECT] C-private primitive form (jax.extend.core.Primitive + jax.interpreters ad/batching/mlir): Public jax.custom_jvp (primal while_loop, jvp = jvp of scan) passes forward, grad, jvp, both Hessian orders, vmap(grad), remat and export in the spike; the private form adds JAX-internals churn (two names already removed in 0.11) for no capability.
- [REJECT] C-public custom_vjp form: Breaks forward-mode (jvp/jacfwd/hessian raise TypeError); aminx uses forward-mode (host/runner.py, utils/forward_jac.py). custom_jvp covers both modes.
- [REJECT] B. Trace infers and rewrites user jaxprs per context: Rewriting user ops needs a jaxpr interpreter that survives nested pjit/vmap/custom rules and fights jit caching, and it violates the anti-goal of unverifiable magic. Kept as analysis only: jaxpr inspection verifies claims and reports hazards; only xtrax's own intent sites are resolved.
- [REJECT] E. AutoGraph-style runtime source rewrite: Runtime AST rewriting is the magic the frame excludes and duplicates what intent functions express directly. AST/CST is kept for authoring-time codemods/lint and for site naming/source locations in errors.
- [MERGE] G. Rewrite xtrax primitives inside a traced jaxpr (plan pass as jaxpr rewrite): Merged into the two-pass design: decisions come from an abstract plan pass and are applied in a second trace by site key with sequence validation (spike passed), avoiding a jaxpr rewriter.
- [DEFER] Reverse-mode memory peak when xtrax.compile is called under differentiation: Critic: primal while_loop budget understates the scan-residual peak under grad. Candidate: detect differentiation from argument tracer types at call time and plan for the reverse peak. Needs a spike before the plan is final.
- [ACCEPT] Reverse-mode memory peak: per-path decisions instead of tracer inspection: custom_jvp already separates paths: the primal rule runs only undifferentiated, the jvp rule only under differentiation. Each loop/map site gets two decisions from the resolver — primal (while_loop budget) and differentiated (scan + residuals budget, optionally with a checkpoint policy) — so the budget is right on both paths without inspecting tracer types. Required test: peak memory under grad stays within the differentiated decision's budget. Supersedes the deferred tracer-inspection candidate.

## Pre-mortem Record
**User:** Pre-mortem — six months on, it failed because:
1. Path-dependent site sequences. Under grad the custom_jvp rule traces the loop body again (scan form), so intent sites nested in a loop body are visited on a different path than in the undifferentiated plan pass; lax.cond/switch trace every branch; jax.checkpoint and custom rules re-trace bodies. The sequence check fired on legitimate code, users hit 'site not reproducible' errors and turned xtrax.compile off. Prevention: site keys are hierarchical (parent site, path = primal|diff|branch i) and validation is per path; the plan pass also traces the differentiated path (jax.linearize of the abstract fn) when the context allows differentiation; a test matrix covers nested loop-in-map, map-in-loop, cond branches, remat and grad.
2. No adoption. Consumers kept jax.vmap/lax.scan because migration showed no measured win on their own workloads. Prevention: the MVP lands on one real workload with a pre-registered, measured outcome — candidates already documented: the 512-step autoregressive decode (scan codegen >20 min vs while) and the ChunkedMap-around-while_loop compile hang; codemods ship with the MVP.
3. Two sources of truth. Legacy BatchPlanner.plan(specs) callers and the new resolver drifted (different batch sizes for the same axis, export composer refusing what the resolver allowed). Prevention: the resolver calls BatchPlanner and the export composer's constraints become resolver rules with one shared table; the legacy entry point is a thin wrapper.
4. Plan-pass cost. A second abstract trace doubled trace time on large models (AF3/Boltz-scale bodies in plegadx), where tracing already takes minutes. Prevention: measure trace-time overhead on the largest consumer model before release; cache Plans on disk by (fn identity/source hash, avals, ctx).
5. Opaque errors. Failures surfaced inside custom_jvp/closure_convert stacks without pointing at user code. Prevention: every resolver/validation error names the site (user name or source location), the path, and the decision; a reviewed set of deliberately failing examples.
6. Acceptable failure: JAX itself ships while-unless-differentiated or memory-planned maps — then xtrax's intent functions become thin aliases, which costs little because they are drop-in.
