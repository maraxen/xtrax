## Pre-mortem Record
**User:** Six months in, definitively failed. The autopsy, ranked by likelihood x severity:

PM-1 (HIGHEST — the evaluator monopoly leaked): "Immutable" wasn't. The SHA-pin (F2) covered the evaluator script but not its full transitive surface — a splits path, a normalization constant, a dependency version, or a data file the evaluator imported. A candidate mutated the uncovered surface and the judge drifted; the loop optimized against a moving target and every "improvement" after week 3 was against a different evaluator than week 1's. F2 checked the wrong hash boundary. This is the one non-recoverable event and it fired too late / covered too little. Root cause: we hashed the evaluator FILE, not the evaluator's complete closure (code + splits + metric-defs + pinned deps + config).

PM-2 (silent semantic reward-hacking through an under-specified scalar dict): The flat dict[str,float] tracked val-metric + wall-clock + memory, but a candidate improved a tracked scalar while degrading an UNtracked property (numerical stability under shift, or a correctness invariant the evaluator never measured). F7 only guards metrics IN the dict; the dict was incomplete. This is Cerebras "faster-but-more-memory" generalized: what you don't measure, the agent games. The fork-2 decision (scalar over tree rubric) is not the culprit — evaluator COMPLETENESS is. We shipped without a documented, reviewed list of invariants the evaluator must assert beyond the optimization target.

PM-3 (the #2174 dependency was satisfied by a stub): S1's topology.py never cleanly landed — it stalled on the unresolved list-vs-Mapping boundaries keying (fork 9, a #2174 fork we did NOT resolve here). #2181 mocked the sealed EvaluateFn seam; the mock diverged from the real S4 seam; the F-D entry-criterion validation-gate validated a stub graph and reported PASS. The loop was built on scaffolding that never became load-bearing.

PM-4 (bathos BUILD items became the critical path and shipped partial): The loop needed seed field + stats battery + campaign_edges + sidecar-drift + xtrax<->bathos bridge — all greenfield. Six months in, three of five landed; the loop ran without seed-gating and underpowered confirmatory claims (N<29) leaked out labeled 'held'. We treated bathos work as reuse when §1.4 explicitly marked it BUILD.

PM-5 (information leaked through the SANCTIONED envelope): ORTH-2 redacted raw stdout, and the lint gate confirmed no raw-log read path — but the schema-validated JSON failure envelope itself carried enough structured signal (exact failing shapes, error taxonomy, per-iteration fitness deltas) that the agent reverse-engineered held-out characteristics and overfit. The barrier guarded the channel we designed and ignored the channel we sanctioned.

PM-6 (local-minima escape was theater): restart-from-best-K + Leap-Path fired on schedule (diversity quota mechanically satisfied) but the "structural" mutations were cosmetic — renamed vars, reordered commutative ops — that the SYNTACTIC counter accepted as structural. The loop churned without escaping AND wasted the iterations the runner-up warned about. F5 counted structure syntactically, not semantically.

PM-7 (external-stop shared a process with the loop): F9's controller was an in-process Python driver; "termination outside agent context" was nominally true but a hang/OOM in a candidate wedged the controller too, and a corrupted mid-ratchet git state (crash between commit and reset) destroyed the best-so-far lineage with no transaction boundary. The thing we deferred (praxia contract-DAG budget enforcement) was load-bearing for F9 robustness, and git-as-memory had no crash-atomicity.

MITIGATIONS to fold into the ACs/synthesis: (1) PM-1 -> F2 hashes the evaluator's COMPLETE CLOSURE, not the file; entry AC asserts closure enumeration is exhaustive and any unlisted path read by the evaluator fails loud. (2) PM-2 -> add an evaluator-completeness gate: a reviewed invariant manifest the evaluator must assert (correctness/stability floors) beyond the optimization target; sanity-check on synthetic ground truth (BATHOS rule) before the loop trusts it. (3) PM-3 -> make the F-D entry gate validate against the REAL S4 seam signature, with a no-stub AC (grep-gate that the seam import resolves to src/xtrax, not a test double). (4) PM-4 -> gate loop-start on a bathos-capability probe: refuse to start confirmatory campaigns until seed field + stats battery are live (machine-checkable, not attested). (5) PM-5 -> the info-barrier lint must also bound envelope CONTENT (whitelist of fields, no per-split granularity), and cross-iteration fitness delta exposure is itself rate/precision-limited. (6) PM-6 -> F5 diversity must be measured semantically (AST/graph-structural diff over the composition IR, not text), reusing the #2174 typed-IR. (7) PM-7 -> external-stop runs as a SEPARATE process/watchdog with a kill authority the loop process cannot revoke; git-as-memory writes are crash-atomic (tmp-commit + fsync + atomic ref update) with a recovery AC that a mid-ratchet crash never loses best-so-far.
