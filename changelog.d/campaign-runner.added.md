- `xtrax.campaign` and `xtrax campaign plan|run|status|verify` (#267): a resumable work-item runner. `plan` expands a `CampaignSpec` TOML into a manifest of hashed rows; `run` executes a `--fn module:function` per row with the `local-seq`, `local-pool` or `slurm` executor. Each unit is a zarr group committed under a lease with a done marker and content digest; resume reuses a unit only when its marker and (by default) its digest match, and records the reuse in `reuse_log.jsonl`. `verify --deep` recomputes digests and quarantines bad units. A local `campaign run` writes one run-ledger row (kind `eval`, `context.verb = "campaign"`).
- `xtrax campaign run --executor slurm` writes an array script for the pending rows and queues nothing. `--slurm-partition`, `--slurm-gpus` (default 0), `--slurm-time`, `--slurm-cpus`, `--slurm-mem`, `--slurm-job-name` and `--slurm-max-concurrent` set its resources and are refused with a local executor (#3318). The script runs the generating environment's `xtrax` console script by absolute path, puts the `--fn` module's source root on `PYTHONPATH` when it lies outside that environment, and exports the resolved, absolute run-ledger root, so array tasks work under `sbatch --export=NONE` and from any working directory. `SlurmArrayExecutor` takes the matching `mem`, `launcher`, `pythonpath`, `env` and `env_comments` arguments, and its `gpus` default is 0.
