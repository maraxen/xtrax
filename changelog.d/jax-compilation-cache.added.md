- `xtrax.jax_cache`: one configurable persistent JAX compilation cache. `configure()` resolves the directory through explicit argument, `$XTRAX_JAX_CACHE_DIR` (`none` or empty disables), `jax_compilation_cache_dir` under `[tool.xtrax]` in the nearest `pyproject.toml`, then `${XDG_CONFIG_HOME:-~/.config}/xtrax/config.toml`, and is off otherwise. There is no default path in library code. `cache_dir_source()` and `resolve()` report which layer decided without touching JAX; `configure()` returns `CacheSetting(dir, source, enabled, ...)`, is idempotent, logs the deciding layer at INFO, and never initialises the JAX backend. A malformed config file raises `ValueError` naming it; an unwritable directory raises `JaxCacheDirError`. Knobs `jax_cache_min_compile_time_secs`, `jax_cache_min_entry_size_bytes`, `jax_cache_max_size_bytes` (needs `filelock`) and `jax_cache_namespace` map to JAX's persistent-cache flags. By default entries go under `jaxlib-<version>/cpu-<hash of host CPU flags>` inside the configured directory, because JAX's cache key does not carry the host CPU feature set; `namespace = "none"` uses the directory as given.
