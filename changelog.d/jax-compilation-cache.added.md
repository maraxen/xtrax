- `xtrax.jax_cache`: one configurable persistent JAX compilation cache. `configure()` resolves the directory through explicit argument, `$XTRAX_JAX_CACHE_DIR` (`none` or empty disables), `$JAX_COMPILATION_CACHE_DIR`, `jax_compilation_cache_dir` under `[tool.xtrax]` in the nearest `pyproject.toml`, then `${XDG_CONFIG_HOME:-~/.config}/xtrax/config.toml`, and is off otherwise. There is no default path in library code. `cache_dir_source()` and `resolve()` report which layer decided without touching JAX; `configure()` returns `CacheSetting(dir, source, enabled, ...)`, is idempotent, logs the deciding layer at INFO, and never initialises the JAX backend. A malformed config file raises `ValueError` naming it, an unexpanded `$VAR` or `~` in a path raises `JaxCacheConfigError` naming the layer, and an unwritable directory raises `JaxCacheDirError`. Knobs `jax_cache_min_compile_time_secs`, `jax_cache_min_entry_size_bytes`, `jax_cache_max_size_bytes` (needs `filelock`) and `jax_cache_namespace` map to JAX's persistent-cache flags. Entries go under `jaxlib-<version>/` by default (JAX's key already includes the version, so this costs no hits and eases pruning); `namespace = "cpu-flags"` adds a host-CPU-ISA segment, `"none"` uses the directory as given. JAX's CPU cache key already carries an accelerator fingerprint that an independent probe found to change with the target ISA, so no CPU segment is applied by default; that evidence is indirect and awaits a fingerprint comparison on two cluster node types. `prune_corrupt()` deletes entries that no longer decompress, which JAX's non-atomic writes can leave after a preempted job.
