- `xtrax.fileguard`: file-count (inode) guard for shared scratch, lifted from alynxr's `storage.py`. `FileCapGuard` reads the real quota and refuses a write whose projected count exceeds `cap_fraction` (default 0.95) of the limit, re-reading every `reread_every` files. On Lustre it uses `lfs quota` and refuses rather than fall back to a filesystem-wide `df -i`. Elsewhere (NFS, ext4) it enforces the per-user `quota -w` row for the path's device alongside the `df -i` filesystem reading, and emits `quota_limit_unknown` when no per-user row exists (on a shared NFS server `df -i` is the whole server, never the user's cap). On MIT ORCD clusters (Engaging) it reads the root-written `~/orcd/.quota` report for the per-user HOME, SCRATCH and POOL file counts, refusing a stale or unparseable report. On a setgid directory it also enforces the owning group's quota. `check_concurrency_slack` refuses at plan time when N concurrent guards could jointly overshoot. Events go through an injectable emitter (`cisternal.emit_event` when installed, else logging). The core is stdlib-only and Python 3.9 compatible; `node_source()` returns it for embedding in cluster scripts run under a registered Python >= 3.9.
